## 【通用规则】（每周指令都要带上这段）

**项目背景**：「思辨场」是 2026 微信小程序开发大赛参赛项目（截止 2026-10-17），一个多 AI 角色的思辨训练小程序。三层模式：L1 单人苏格拉底追问 / L2 专家+苏格拉底双人共修 / L3 三方 AI 辩论场。技术路径以仓库内 `docs/tech-roadmap-v2.md` 为唯一权威，与本指令冲突时以 roadmap 为准。

**硬性红线（违反任何一条都算任务失败）**：

1. **免费 Token 额度只能从小程序端（wx.cloud.extend.AI）、云函数/云托管（wx-server-sdk）、云开发控制台三个来源消耗。严禁在 AI 编程工具、本地脚本、Web SDK 中直连模型接口测试**——违规会导致资源包被暂停。所有涉及模型效果的测试，必须通过云函数或微信开发者工具预览完成。
2. 混元接口返回的 `note` 字段（"以上内容为AI生成……请勿删除或修改本标记"）**不得在代码中删除或篡改**。
3. 用户输入进入对话前必须过 `security.msgSecCheck`；AI 输出启用流式审核，收到 `finish_reason=sensitive` 时撤回已上屏内容并显示兜底文案。
4. 对话类代码一律流式（SSE）实现，渲染端 token 缓冲约 120ms 批量 `setData`，禁止逐 chunk 刷新。
5. 所有网络/模型调用必须有错误处理，云函数统一返回 `{ code: 0, data: {...} }` 或 `{ code: -1, msg: "..." }`。
6. 不要引入 v2 目录结构之外的新依赖、新服务；不确定的选型先在产出中标注 ⚠️ 待确认，不要自作主张。

**技术约定**：

- 模型：实时对话用 `hy3-preview`，报告生成用 `hy3`，统一在 `miniprogram/config.js` 配置，禁止散落硬编码。
- 小程序端调模型示例（官方 API，基础库版本要求以微信官方文档为准，W1 需确认并记录）：

```javascript
wx.cloud.init({ env: "<云开发环境ID>" });
const ai = wx.cloud.extend.AI;
const provider = ai.createModel("cloudbase");
const res = await provider.streamText({
  data: {
    model: "hy3-preview",
    messages: [{ role: "user", content: "你好" }],
  },
});
for await (const chunk of res.textStream) { /* 流式文本 */ }
for await (const event of res.eventStream) {
  // 完整事件流；结束时 event.data === "[DONE]"
  // event 中含 usage（prompt_tokens/completion_tokens）与 note 字段
}
```

- 数据库集合：`sessions` / `reports` / `users` / `user_quota` / `topics_v1` / `token_usage` / `votes` / `eval_runs`，字段定义见 tech-roadmap-v2.md 第 3.4-3.5 节。
- 每次模型调用完成后，必须把 `usage` 写入 `token_usage` 表（openid、mode、model、prompt_tokens、completion_tokens、createdAt）。

6. **合规基线**

   - `miniprogram/utils/security.js`：发送前调用封装。
   - AI 标识组件：对话页常驻"AI 生成"角标 + 免责声明文案。
7. 把苏格拉底 prompt 初稿放入 `prompts/socrates.md`（可直接采用 tech-roadmap v1 存档中的苏格拉底角色 prompt），前端经 `miniprogram/utils/prompts.js` 读取。

## W2 指令：核心对话 + 评测体系 + Token 实测

**本周目标**：L1 单人模式完整链路 + Prompt 评测体系 + 成本实测校准。
**前置**：W1 验收全部通过。

### 任务清单

1. **苏格拉底 prompt 定稿**（`prompts/socrates.md`）
   - 核心约束：永远不直接给答案/评价；每次只追问一个逻辑环节；回复 ≤3 句；不用感叹号；追问策略按优先级：预设 → 证据 → 边界 → 后果 → 定义；用户困惑时换角度提问而非解释；涉及政治敏感话题时礼貌终止并引导换话题。
2. **评测体系**
   - `prompts/evals/cases.json`：30-50 条用例，结构 `{ id, input, category, red_lines, focus }`。必须包含对抗样本：诱导 AI 直接给答案的（"别问了直接告诉我"）、跑题的、情绪化的、含敏感话题的、逻辑明显有漏洞的（滑坡/稻草人/循环论证各至少 3 条）。
   - `prompts/evals/rubric.md`：评分标准——是否泄露答案（一票否决）/追问是否命中输入中的真实假设/是否复读上一轮问题/语气是否克制。
   - `evalRunner` 云函数：读取 cases，逐条以苏格拉底 prompt 调用模型（hy3-preview），再用 hy3 做一次裁判调用按 rubric 打分，结果写 `eval_runs` 表（含整体通过率）。**注意：一次全量评测约消耗 10 万 Token，每天最多跑一次。**
3. **对话状态机**（`pages/socrates/`）
   - 流程：进入页面 → 校验当日配额（user_quota）→ 用户输入 → msgSecCheck → 组装上下文（system + summary + recent 8 轮 + 用户消息）→ 流式调用 → 回复完成 → sessionStore 落库 → 等待下一轮。
   - 轮次达到 10 轮：停止追问，提示进入报告环节（报告页 W3 实现，本周先占位跳转）。
   - 配额用尽：友好提示 + 引导查看历史报告。
4. **sessionStore 云函数完整实现**
   - `get`：返回 recent + summary + round。
   - `append`：追加本轮 user/assistant 消息到 recent；recent 超过 8 轮时裁剪最旧轮次；第 9 轮起触发滚动摘要（一次 hy3 调用，把被裁剪的轮次并入 summary，≤300 字），摘要异步执行。
5. **配额与监控**
   - `utils/quota.js` + user_quota 表：按 openid+日期记录 l1Used/l2Used/l3Used，跨日自动重置。
   - token_usage 落库确认覆盖全部调用路径。

### 验收标准

- [ ] L1 完整走满 10 轮对话不中断、不串上下文、不崩
- [ ] 第 9 轮后滚动摘要生效，上下文未无限增长（打印本轮调用的 prompt_tokens 观察）
- [ ] evalRunner 全量跑通，输出通过率报告；苏格拉底 prompt 迭代至**通过率 ≥80%**
- [ ] 配额用尽后无法发起新会话
- [ ] **Token 实测**：统计 L1 单会话真实消耗（10 轮+摘要），把 tech-roadmap-v2.md 1.3 节的估算值替换为实测值（标注样本数）

## W3 指令：思辨报告 → 单人模式全闭环（保底提审版本）

**本周目标**：对话 → 报告 → 评分 → 分享，L1 全闭环。★ 本周结束时的版本是最低参赛完整度，质量优先。
**前置**：W2 验收全部通过。

### 任务清单

1. **generateReport 云函数**
   - 输入 sessionId，读取该会话全部轮次。
   - 调用一（hy3）：生成结构化标注 JSON——`strategyTags`（每轮苏格拉底追问的策略类型：预设/证据/边界/后果/定义）、`fallacies`（用户论证中的谬误，含用户原话 quote）、`logicChain`（{nodes, edges} 论证链）、`highlights`（用户最精彩的 1-2 句发言）。要求模型严格输出 JSON，做解析失败重试。
   - 调用二（hy3）：基于标注结果生成自然语言报告（≤300 字，克制、不吹捧）。
2. **评分算法**（云函数内实现）
   ```
   基础分（30）：min(轮次 × 6, 30)
   深度分（40）：五种追问策略各 8 分，按 strategyTags 覆盖数计
   修正分（30）：30 - 谬误类型数 × 6，下限 0
   ```
3. **报告页**（`pages/report/`）：评分环、谬误列表（可点击定位原话）、深度分雷达或条形展示、自然语言报告、AI 生成标识。
4. **logic-chain 组件**（Canvas 2D 自绘，**禁止用 D3**）：论证链节点图，支持点击节点高亮。布局用简单分层算法即可，视觉干净优先。
5. **分享入口**：报告页右上角转发（share 卡片文案 + 缩略图），海报功能 W6 实现，本周留占位按钮。

### 验收标准

- [ ] 一次完整对话结束后 10 秒内生成报告（含两次模型调用）
- [ ] 评分与公式一致（手工核算 3 个样例）
- [ ] 逻辑链 Canvas 在中低端安卓真机正常渲染、可交互
- [ ] JSON 解析失败有重试且最终兜底（解析失败时评分降级为仅基础分，不报错白屏）
- [ ] 转发卡片正常显示

## W5 指令：辩论场（L3）

**本周目标**：正方/反方/裁判三方辩论，围观 + 投票 + 终局发言。
**前置**：W4 验收全部通过。**降级触发：本周日未达标 → 辩论从 3 轮压缩为 2 轮，其余不变。**

### 任务清单

1. **角色 prompt**
   - `debater_affirmative.md` / `debater_negative.md`：temperature 由状态机参数控制（0.9）；约束：≤150 字；必须先回应对方上一轮论点再立论；每轮必须提出至少一个新论证角度（禁止复读己方旧论点）；即使持方也要承认对方合理之处。
   - `judge.md`：temperature 0.2；严格输出 JSON：`{ affirmative: {strengths[], weaknesses[]}, negative: {strengths[], weaknesses[]}, verdict_note }`，禁止和稀泥、禁止立场偏袒。
2. **L3 状态机**（`pages/debate/`）
   - 每轮时序：正方流式发言 → 反方流式发言（context 含正方本轮）→ 裁判 JSON 点评（渲染为双方亮点/漏洞卡片）→ 展示本轮投票条 → 下一轮。
   - 每个角色发言前显示"XX 正在组织语言"占位态。
   - 3 轮结束后：展示立场变化曲线（用户每轮投票记录）→ 用户可提交自己的观点（一次输入）→ 裁判对用户观点做一次点评（一次调用）。
   - 投票写 `votes` 表（openid、topicId、round、side）。
3. **辩论舞台 UI**（`components/debate-stage/`）：三角色分色对话区、投票条、立场变化可视化（Canvas 简易折线即可）。
4. **辩题白名单**：生成 50 条候选辩题（覆盖科技/人文/社会/生活/哲学，避开一切政治、宗教、民族、性别对立话题），输出到 `docs/topics-candidates.md` **交人工审核**；人工确认后再灌入 `topics_v1` 集合。⚠️ 未经人工确认的辩题禁止入库。
5. **首页入口**：L3 入口从"话题列表"进入（白名单辩题），不支持自由输入辩题（赛前范围）。

### 验收标准

- [ ] "996 是奋斗的体现"完整 3 轮辩论，三轮论点有演进、无明显复读
- [ ] 裁判 JSON 稳定可解析（连续 5 场无解析失败），点评分别覆盖双方
- [ ] 每轮投票可用，立场曲线正确
- [ ] 用户终局发言 + 裁判点评闭环
- [ ] topics_v1 全部来自人工确认的白名单

## W8 指令：压测外推 + 提报材料

**本周目标**：用数据支撑提报，保障评审期稳定。
**前置**：已提审（审核往返期间只修审核反馈问题）。

### 任务清单

1. **成本报告**（`docs/cost-report.md`）
   - 汇总 token_usage 表实测数据：分模式单次会话 Token 均值（附样本数）、日均消耗趋势。
   - 外推公式：`可持续 DAU = 剩余 Token ÷ 剩余天数 ÷ 人均日耗实测值`；输出 300 / 500 / 1000 DAU 三档情景结论。
   - 资源点消耗核对：云函数/数据库实际点数消耗 vs 月度配额。
2. **稳定性专项**
   - 断网重连：对话中断网 10 秒恢复，会话状态不丢、不重复扣轮次。
   - 切后台 5 分钟恢复：流式中断后重试路径正确。
   - 限流验证：单用户高频触发 2QPS 限制，返回友好提示；配额跨日重置正确。
   - 模型异常：模拟超时/限流错误，验证退避重试与兜底文案。
3. **演示视频素材**：按 tech-roadmap-v2.md W8 分镜准备录屏环境（预置最佳效果的历史会话，避免录制时现场翻车；准备 2 个保底辩题）。
4. **提报文档 + README 终版**
   - 全部数据替换为实测值（删除所有 ⚠️ 估算标注，或明确标注为赛后规划）。
   - 技术叙事按 W1 验证结论执行：端侧推理验证失败则不提，突出"客户端流式编排 + 多角色差异化 + 评测驱动的 prompt 工程 + 零成本架构"。
   - README：架构图（更新为 v2 实际架构）、实测数据表、运行方式、目录说明、License。
