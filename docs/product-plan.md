# AI「思辨场」— 产品架构与开发计划

> 2026微信小程序开发大赛参赛方案 | 主题：与AI共生  
> 赛道：教育学习 / 效率工具  
> 标签：多Agent架构、苏格拉底教学法、批判性思维训练

---

## 一、产品定位

**一句话**：一个用多AI角色制造认知冲突、逼你深度思考的思辨训练场。

**核心差异化**：不做"给答案的AI老师"，做"逼你动脑的AI智囊团"。引入前沿多Agent架构，从"人机对话"升级为"人机共思"。

**目标用户**：18-35岁，有学习和思考意愿，但苦于被动接收信息太多、深度思考太少的人。

---

## 二、核心功能：三层思辨场

### 层级一：单人磨刀（苏格拉底追问）

```
[你] 提出观点
  ↕
[苏格拉底·马尔维斯] 只追问，不给答案
  ↓
思辨报告：逻辑链图谱 + 认知偏差标记 + 论证评分
```

- 用户输入任意观点/看法（如"996是奋斗的体现"、"学历史没用"）
- 苏格拉底Agent通过层层反问揭示隐藏假设、证据漏洞、逻辑跳跃
- 单次对话5-15轮，结束后生成可视化思辨报告
- **端侧推理**识别常见逻辑谬误（滑坡、稻草人、循环论证等），不耗Token

### 层级二：双人共修（专家 + 苏格拉底双Agent）

```
[你] 提出想学的概念
  ↕
[专家Agent] 讲解原理、举例、给框架
  ⇅
[苏格拉底Agent] 追问你对原理的理解、测试边界
  ↓
双重评估：知识掌握度 × 思辨深度
```

- 用户输入想学的话题（如"量子纠缠"、"通货膨胀"、"柯里化"）
- 专家Agent先做原理讲解（用类比和案例），苏格拉底Agent立即追问检验
- 两个Agent交替发言，用户一直接球
- 适合知识学习+思维训练同步进行

### 层级三：三人围观（AI辩论场）

```
[正方Agent] ←→ [反方Agent] ← [裁判Agent]
         ↕（你围观+投票+最后发言）
```

- 用户输入争议话题或从话题广场选择
- 正方/反方/裁判三个Agent展开3轮辩论
- 用户全程围观，每轮后可以做立场投票
- 辩论结束后用户可以提交自己的观点，由裁判Agent点评
- **社交裂变核心场景**：辩论截屏天然适合分享到群聊和朋友圈

## 三、社交功能

| 功能 | 说明 |
|------|------|
| 群聊辩论赛 | 群内发起话题→群友各自与AI辩论→排名→群内发榜 |
| 思辨段位 | 青铜→白银→黄金→钻石（基于追问轮数、谬误识别率、辩论胜率） |

| 话题广场 | 用户投稿辩论话题，投票热门话题 |

## 四、技术架构

### 4.1 整体架构

```
┌─────────────────────────────────────┐
│           微信小程序前端              │
│  ChatUI Kit（对话组件）               │
│  ├ 单人模式 UI（单角色）              │
│  ├ 双人模式 UI（双角色交替）          │
│  └ 辩论场 UI（三角色同屏）            │
├─────────────────────────────────────┤
│          微信端侧推理引擎             │
│  ├ 逻辑谬误分类（3亿参数）            │
│  ├ 情感倾向检测                       │
│  └ 论证结构提取                       │
├─────────────────────────────────────┤
│        云开发 CloudBase               │
│  ├ 云函数：Agent编排 + 对话管理       │
│  ├ 云数据库：用户数据 + 思辨记录      │
│  └ 云存储：海报素材                   │
├─────────────────────────────────────┤
│         混元 Hy3 LLM                  │
│  ├ System Prompt 切换（角色工厂）     │
│  ├ 多轮对话记忆管理                   │
│  └ 思辨报告生成                       │
└─────────────────────────────────────┘
```

### 4.2 核心技术决策

**多Agent编排**：不是跑多个模型，而是同一LLM接口切换system prompt。云函数串行编排对话流：

```python
# 双人模式伪逻辑
def dual_agent_session(user_input, expert_prompt, socrates_prompt):
    expert_reply = llm.chat(expert_prompt, user_input)       # 专家讲
    socrates_reply = llm.chat(socrates_prompt, expert_reply)  # 苏格拉底追问
    return expert_reply, socrates_reply
```

**端侧推理分流**：先用端侧3亿参数模型做轻量级判断（谬误分类、论证框架提取），只有端侧置信度低时才走云端LLM。目标是端侧处理70%的分析工作。

**对话记忆**：每个会话用云数据库存储最近20轮对话摘要（不是全文），作为LLM的上下文注入。避免上下文窗口溢出，同时控制Token消耗。

### 5.2 Token消耗测算

| 场景 | 每次Token | 10亿Token可支撑 | 日活2000人可用 |
|------|:---:|:---:|:---:|
| 单人苏格拉底（5-15轮） | ~2000 | 50万次 | 250天 |
| 双人专家+苏格拉底 | ~3500 | 28万次 | 143天 |
| 三人辩论场（3轮） | ~5000 | 20万次 | 100天 |
| 思辨报告生成 | ~800 | 125万次 | — |
| 混合场景（日均1次+报告） | ~3000 | 33万次 | 167天 |

**结论**：即使日活达到2000人，免费额度覆盖比赛评审期（2个月）绰绰有余，且有大量余量应对评委集中体验期的峰值。

### 5.3 降本措施

- 端侧处理70%逻辑分析，减少云端调用
- 对话摘要而非全量存储，控制上下文长度
- 辩论场使用预设话题模板，减少长尾生成
- 海报生成走云函数+Canvas，不用AI生图接口
- 冷启动阶段用固定话题库，不走动态生成
